# Verse8 실시간 멀티플레이 기술 검증 (테스트 룸, 최대 4인)

작성 2026-10-21. 대상: Verse8 Agent8 GameServer SDK 2.0 (`@agent8/gameserver` 2.0.1, `@agent8/gameserver-node` 2.0.1, `@agent8/deploy` 1.5.5).

## 1. 결론 요약

| 구분 | 상태 |
|---|---|
| SDK 판정 | **A — 2인 테스트 룸 구현 가능** (룸·상태 푸시·브로드캐스트·throttle 호출이 공식 지원). 단, 서버 물리 없음 등 TPS 제약 있음 (4장) |
| 구현 | 완료: 서버(`server/src/server.ts`), 네트워크 레이어(`src/net/`), 디버그 패널, `?net=1` 모드 |
| 로컬 검증 | 서버 로직 16/16 통과 (공식 로컬 하네스), 클라이언트 게임 모드 레이어 주입 테스트 통과 (네트워크 아님) |
| Verse8 배포 환경 검증 | **일부** — Verse8 저장소(develop) 푸시로 서버가 preview verse에 자동 배포됨. 같은 PC 두 탭(alice/bob)으로 실서버 연결·룸·피해·리스폰·퇴장 확인 (7장). 다른 기기·네트워크 2인은 미측정 |
| 최종 판정 (현재) | **기술적 개선 및 추가 검증 필요** — 다른 기기·네트워크 2인(시나리오 B~E) 결과로 다시 판정 |

## 2. 공식 문서·SDK에서 확인한 사실 (추측 없음)

출처: https://docs.verse8.io/ko/docs (Game Server 섹션), npm 패키지 소스.

| 항목 | 확인 내용 |
|---|---|
| 서버 실행 | isolated-vm. 요청마다 새 `Server` 인스턴스, `setTimeout`/`setInterval` 없음, 모든 메서드가 공개 엔드포인트 |
| 반복 처리 | `$roomTick(delta, roomId)` 활성 룸마다 200ms 주기 (느리면 건너뜀) |
| 원격 호출 | 일반·fire-and-forget: **함수 이름당 초당 10회** (클라이언트에서 셈). `throttle: ms`(최소 30ms): 제한 없음, 기본 leading-only(창 안 호출 버림), 30초 타임아웃 |
| 상태 푸시 | 구독자에게 최대 30ms마다 (trailing, 전체 스냅샷) |
| 메시지 | `$room.broadcastToRoom` / `sendMessageToUser` / `onRoomMessage`: fire-and-forget pub/sub (ack·재시도 없음) |
| 룸 | 매칭 함수가 roomId 반환 → 클라이언트 `joinRoom`. 훅 onRoomCreate/Join/Disconnect/Leave/Destroy. 끊김 30초 유예. **onRoomJoin에서 거절하면 SDK가 재시도만 반복** → 정원은 매칭 함수에서 거절해야 함 |
| 동시성 | 훅·호출이 동시에 실행 → 읽기-수정-쓰기는 `$lock` |
| 로컬 2탭 | 같은 브라우저 탭은 익명 계정 공유 → `?account=alice` / `?account=bob` (인증 토큰이 없을 때만) |
| 클라이언트 | 문서는 React 훅 기준. 패키지가 `GameServer` 클래스를 export → React 없이 사용 (훅 쪽 재연결 정책·connectionStatus는 React 스토어에 있어 미사용) |
| 배포 | `@agent8/deploy` 기본 모드: 토큰 없이 임의 verse 생성 후 `server/dist/server.js` **와 `dist/` 전체** 업로드, `.agent8.lock`·`.env`에 `VITE_AGENT8_VERSE` 기록. `--preview`/`--prod`는 `V8_ACCESS_TOKEN` + 계정 필요 |

## 3. 구조

```
Game Logic   src/core/Game.ts …            (기존, ?net=1 아니면 변화 없음)
Game Mode    src/net/NetGameMode.ts        서버 결과 → 게임 적용, 원격 탄 연출(기존 ToyBullets 경로)
             src/net/RemotePlayer.ts       원격 캐릭터: 보간 표시 + 히트박스(기존 CharacterHitboxes)
Network      src/net/NetSession.ts         룸 흐름·상태 패킷·이벤트
             src/net/NetClient.ts          SDK 래퍼·시뮬레이션·통계
             src/net/SnapshotBuffer.ts     보간 버퍼 (순수 계산)
Shared       src/net/shared/protocol.ts    서버·클라이언트 공용 규칙·메시지 형식
Server       server/src/server.ts          Verse8 Server 클래스
UI           src/net/NetDebugPanel.ts      NETWORK TEST 패널 (F9)
```

- `?net=1` 일 때만 네트워크 모드: 봇 0명, 규칙 `NET_TEST_RULES`(2인, 30분, 999킬). 없으면 싱글플레이 그대로.
- 캐릭터 6종·능력치·속도·무기·VFX·ADS·이동·헤드샷 1.5·사망 X눈·AI 코드는 바꾸지 않음. `presentShot`은 연출 함수(`presentShotFx`)로 나눠 원격 탄과 공유만 함.

### 동기화 방식

| 대상 | 방식 | 권한 |
|---|---|---|
| 이동·자세·무기 | 50ms(20Hz)마다 `st` throttle 호출(창 40ms) → 룸 사용자 상태 → 상대에게 푸시 → 120ms 지연 보간 (넘으면 100ms까지 외삽) | 클라이언트 (서버는 숫자 범위만 검사) |
| 사격 연출 | 같은 패킷에 탄 목록 → 서버 `fx` 브로드캐스트 → 상대 화면에서 보간 시점에 맞춰 재생 | 클라이언트 |
| 명중 | 쏜 쪽 로컬 히트스캔이 원격 히트박스를 맞히면 "맞혔다" 주장만 전송 | 서버가 검증 |
| 피해·체력·사망·킬/데스·리스폰 | 서버가 무기 표(`NET_WEAPONS`)로 피해 계산(헤드샷 1.5·샷건 거리 감소 포함), 룸 상태 `players`에 저장, `hits` 브로드캐스트 | **서버** |
| 리스폰 | 클라이언트 요청 → 서버 시각으로 2.5초 지났을 때만 승인, 보호 2초 (공격하면 해제) | **서버** |

라이플 600rpm = 초당 10발 = 일반 호출 한도와 같음 → 사격을 호출 1회씩 보내면 한도 초과. 그래서 사격·명중을 50ms 상태 패킷에 묶어 보냄 (throttle 호출은 한도 없음).

### 서버 검증 (명중 주장)

공격자 생존, 대상 생존·보호 아님, 사거리, 서버가 아는 두 위치 거리와 주장 거리 차 ≤ 4m, 무기별 연사 토큰(rpm×1.25, 순간 3발), 패킷 안 캐릭터 명중 탄 수 이하. 거부되면 공격자에게 `rej` (패널 "거부" 수·사유).

**검증 못 하는 것**: 벽 관통·시야 (서버에 맵 콜라이더·물리 없음), 정확한 히트박스 위치. → 서버 권한은 "피해 계산·체력 소유·명백한 부정 차단" 수준.

## 4. 실시간 TPS 요구사항 비교

| 요구 | SDK 지원 | 비고 |
|---|---|---|
| 20Hz 이상 위치 전송 | O (throttle 무제한, 최소 30ms) | leading-only라 간격을 throttle 창보다 길게 유지해야 함 |
| 상대 위치 수신 | O (상태 푸시 ≤30ms 간격) | 실제 지연은 배포 후 측정 필요 |
| 사격 이벤트 | 부분 (일반 호출 초당 10회) | 패킷 묶음으로 해결 |
| 서버 권한 판정 | 부분 | 피해·체력 O, 시야·충돌 X (서버 물리 없음, 틱 200ms) |
| 서버 주도 시뮬레이션 | X | 타이머 없음, 틱 200ms → 서버 이동 시뮬·지연 보상(되감기) 불가 |
| 룸 2인 제한 | O (매칭 함수 + 자리 배정) | 동시 입장 경쟁 시 3번째는 자리 없이 관전자 → 클라이언트가 스스로 나감 |
| 끊김 처리 | O (30초 유예, onRoomLeave) | |

## 5. 배포 절차

### 현재 방식 (Verse8 저장소)
- 저장소: `gitlab.verse8.io/anjshdkdl99/game-okvf`, 브랜치 `develop`. 푸시하면 플랫폼이 서버를 빌드해 **`<verse>-preview`** 에 배포 (확인: 2026-10-21 푸시 직후 preview verse에서 우리 서버 함수 응답).
- production verse(`<verse>`)는 런치 전이라 게이트웨이가 `409 verse_broken (recovering)` 응답. 런치는 사용자가 직접.
- `.agent8.lock`·`.env`(verse 값)는 플랫폼 관리 파일 — 수정 금지.
- 클라이언트 접속 verse: 개발 서버 = `<verse>-preview`, 배포 빌드 = `.env`의 `<verse>` (SDK 문서 규칙). SDK는 Vite 개발 서버의 사전 번들에서 `import.meta.env`를 못 읽어 `default`로 가므로 `NetClient.targetVerse`가 직접 계산해 넘김.

### 별도 verse로 직접 배포 (저장소 밖에서 실험할 때)

> 배포는 외부 공개 행위. Claude는 실행하지 않음.

```bash
npm run server:test
```

```bash
npm run server:build
```

방법 1 — 서버만 올리기 (게임 빌드·GLB 업로드 안 함, 권장): 빈 폴더에 `server/dist/server.js`만 복사해서 거기서 배포

```bash
mkdir -p ../pop-battle-verse8/server/dist && cp server/dist/server.js ../pop-battle-verse8/server/dist/
```

```bash
cd ../pop-battle-verse8 && npx -y @agent8/deploy
```

생성된 `../pop-battle-verse8/.env`의 `VITE_AGENT8_VERSE=...` 줄을 이 프로젝트 `.env`에 복사 → `npm run dev` 재시작 (Vite는 시작할 때 .env를 읽음). 서버 코드를 고치면 build → 복사 → 같은 폴더에서 다시 deploy (같은 verse에 덮어씀).

방법 2 — 프로젝트 루트에서 배포: `npx -y @agent8/deploy` 는 `dist/`(게임 빌드 전체)도 업로드함. 첫 배포 뒤 `.env`가 생기므로 `npm run build` 후 한 번 더 배포해야 빌드에 verse가 들어감. Verse8에서 이 빌드가 어떤 주소로 열리는지는 SDK 문서에서 확인하지 못함.

확인 (verse를 읽는 `.agent8.lock`이 있는 폴더에서 — 방법 1이면 `../pop-battle-verse8`):

```bash
npx -y @agent8/cli call ping "[1]"
```

## 6. 테스트 방법

### 배포된 게임에서 (Verse8, 실제 2인)

1. A: Verse8 게임 링크 접속 → 시작 화면 **Multiplayer Test** → **Create Room** → Room Code(예: `ABC123`) 표시, **Copy**로 복사(막히면 코드 칸을 직접 선택해 복사).
2. B: **다른 브라우저 또는 다른 기기**, 다른 계정(또는 게스트)으로 같은 링크 → **Multiplayer Test** → 코드 입력 → **Join Room**.
   - 같은 브라우저의 두 탭은 Verse8가 같은 계정을 넘겨 줘서 충돌(중복 로그인)할 수 있음.
3. 대기실에서 Player 1·Player 2 모두 `Connected · Ready`, `Players: 2/2` 확인 → 방장(★, 먼저 만든 사람)이 **Start Test**.
4. 방장은 바로 조작, 상대는 "테스트 시작! 화면을 클릭" → 클릭. 두 사람이 서로 다른 스폰(P1 = A팀 스폰, P2 = B팀 스폰)에서 1초 카운트다운 뒤 시작.
5. 확인: 서로 이동·점프·슬라이딩, 사격 연출, 피격 HP 감소(일반·헤드샷), 사망 X눈·킬로그, 2.5초 뒤 리스폰.
6. 오른쪽 위 테스트 HUD: Room, Player(P1/P2·계정), Players, Server, RTT, My HP, Opp HP, Msgs, Error.
7. 연결 해제: Esc → **Leave Room** (상대 화면에서 바로 사라짐) / 탭 닫기·새로고침 / 와이파이 끄기 (상대 화면에서 숨김 → 30초 안에 돌아오면 복구, 넘으면 퇴장).
8. 문제가 생기면 F9 → NETWORK DEBUG → **로그 복사** (브라우저 콘솔에도 `[net]`).

- 모바일: 게임에 터치 조작이 아직 없음 → 메뉴·대기실 화면은 가로 화면에 맞췄지만 실제 플레이 테스트는 PC 두 대(또는 두 브라우저)로.
- 개발 서버(`npm run dev`)는 `<verse>-preview`, Verse8 게임은 production verse에 접속 → 서로 다른 서버라 섞어서 테스트하지 않기.

### 개발 서버에서

- `http://localhost:5210/?account=alice`, 다른 기기 `http://<PC IP>:5210/?account=bob` (`npm run dev -- --host`). `?net=1`이면 메뉴가 바로 열림, `&verse=<id>`로 verse 직접 지정 가능.
- SIMULATION 값(F9 패널 분홍 칸)은 진짜 네트워크가 아님. 기록할 때 실제 값과 따로 적기.

1. P1: Multiplayer → TDM 2v2 → Create Room → 코드 공유. P2~P4: 코드 입력 → Join Room.
2. 대기실 BLUE 2 / RED 2 (팀 바꾸기). 4명 미만이거나 2:2가 아니면 Start Match 비활성.
3. 방장 Start Match → 4명 모두 3초 카운트다운 → 같은 시점에 GO, 같은 팀은 같은 구역 스폰.
4. 확인: 팀 색(BLUE/RED), 아군 사격 피해 0, 적 피해(헤드샷 1.5배), 사망 X눈·킬로그·리스폰 보호 표시, 상단 점수가 4명 화면에서 같음, 서로 순간이동·연출 중복 없음, 상대별 HP가 각 화면에서 같음.
5. 끝: 팀 20킬 또는 3분 → 4명 동시에 결과(WIN/LOSE, 점수, K/D) → Return to Lobby.
- 예상 로그: `[Room Joined]` ×4 각자, `[Player Joined]`, `[Match Started] … timeLimitMs=180000`, `[Player Killed]`·`[Player Respawned]` 반복, `[Match Ended] reason=score|time`.

**B. 4인 FFA**: A와 같고 FFA 4인 선택. 팀 없음·캐릭터 고유 색, 모두가 적. 15킬 또는 3분 → 1위 WIN, 나머지 LOSE, 1위 동점이면 DRAW. 예상 로그 `[Match Ended] reason=score winners=1`.

**C. 3분 종료**
- 배포 게임: 3분 그대로 진행 → 0:00에 4명 화면이 함께 결과 (서버 틱 200ms 단위라 최대 약 0.2초 + 각자 지연 차이). 킬 수가 같으면 DRAW.
- 빠른 확인(개발 서버, preview 서버): 대기실에서 20초 선택 → 시작 → 20초 뒤 결과, 아무도 안 죽이면 TDM 0:0 DRAW, FFA 모두 0킬이면 DRAW. 패널 Match에 `[테스트 시간]`.
- 예상 로그 `[Match Started] … timeLimitMs=20000` → `[Match Ended] reason=time draw=true`.

**D. 끊김·재접속** (매치 중, 한 명씩)
| | 할 일 | 남은 사람 화면 | 나간 사람 |
|---|---|---|---|
| D1 | Esc → Leave Room | 즉시 사라짐, "나감" 알림, 결과표에 (나감) | 메뉴, 이전 방 버튼 없음 |
| D2 | 새로고침 | 즉시 사라짐 | 메뉴 → "이전 방 다시 입장" → 같은 자리·팀·K/D로 복귀 |
| D3 | 와이파이 끄기 10초 → 켜기 | 캐릭터 숨김 + "연결 끊김" → 다시 입장하면 보임 | 메뉴(나간 화면) → 다시 입장 → 기록 그대로 |
| D4 | 와이파이 끄기 40초 → 켜기 | 30초 뒤 퇴장 처리 | 다시 입장 → 기록 복원 (서버 `gone`에서) |
| D5 | 방장이 Leave Room | 다른 사람이 방장(★), 매치 계속 | |
- 예상 로그: 남은 사람 `[Connection Lost] account=… grace=30s` → (30초 뒤) `[Player Left]`; 돌아온 사람 `[Reconnection Attempted]` → `[Room Joined] … k=… d=…` → `[Reconnected]`; 다른 사람들 `[Player Joined]`.

## 9. 외부 서버 대안 (제안만, 추가하지 않음)

Verse8 실측에서 지연·판정이 부족하면 별도 선택지: 권한 서버를 직접 운영(Colyseus·Nakama·자체 Node+WebSocket 등, 서버 물리·되감기 가능). 비용·운영·Verse8 연동 방식은 별도 검토 필요. 사용자 승인 없이 도입하지 않음.

- 받는 양이 인원²에 비례: SDK가 사용자 상태가 바뀔 때마다 **전원 상태를 통째로** 푸시 (8명·8회/초 → 초당 약 57번 × 8명분). 8명에서 약 60KB/s(≈0.5Mbps) — PC는 문제 없음, 모바일 회선은 미측정.
- 함께 확인(2명): 닉네임·캐릭터 변경 즉시 반영, `hubBye`·끊김 즉시 숨김, 같은 계정 재입장 같은 로비, 로비 안 방 목록, 방 입장 전 로비 퇴장, 대기실 닉네임, 매치 → 새로고침 없이 로비 복귀, 구독 1개 유지.
- 미측정: 서로 다른 기기·회선, 모바일 실기기 FPS·발열, 서버 CPU(플랫폼 지표 없음), 장시간 접속.
- 줄일 방법(검토): 전송 8 → 5~6회/초, 사용자 상태에서 위치만 자주 바뀌게 유지(닉네임·캐릭터는 이미 hello 때만), 로비에서 원격 라이플 숨김(1명당 약 7천 삼각형).
